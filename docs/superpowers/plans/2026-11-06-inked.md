# Inked. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the current image generator with Inked., a static web app that turns a letter into one themed, auto-fitted image to share from a phone.

**Architecture:** The pure logic lives in ES modules with no DOM access (`js/layout.js`, `js/themes.js`, `js/state.js`, `js/export.js`), and Node's built-in test runner tests them. The canvas renderer and motifs consume a resolved style object and draw the image. The UI modules (`app`, `editor`, `sheet`) wire DOM events to state transitions and re-render. There is no build step: `index.html` loads `js/app.js` as a module.

**Tech Stack:** HTML, CSS, vanilla JavaScript ES modules, Canvas 2D, `Intl.Segmenter`, Web Share API, Clipboard API, Node 20+ `node --test` (dev only, zero dependencies).

**Spec:** `docs/superpowers/specs/2026-11-06-inked-design.md`. Mockups are in `docs/superpowers/specs/2026-11-06-inked-mockups/` (`app-ui.html`, `themes.html`, `new-baby.html`, `languages.html`). Read the spec before starting any task. Where the mockups and the spec disagree, the spec wins.

## Global Constraints

- Static files only: HTML, CSS and vanilla JavaScript. No framework, bundler or package install to run or deploy.
- All asset paths are relative, so the site works at `<user>.github.io/<repo>/`.
- Fonts are self-hosted, open-licensed (OFL), with their licence files.
- No network requests other than the site's own files. No analytics. No third-party fonts at runtime.
- Every canvas stays under 16.7 million pixels. Export sizes: Portrait 4:5 at 3x a 1080x1350 layout (3240x4050), Square at 3x 1080x1080 (3240x3240), Story 9:16 at 2.75x 1080x1920 (2970x5280).
- Every storage call is wrapped in try/catch. The app works with storage unavailable.
- Vermilion `#D0533A` is used only for the wordmark dot, the selected-chip dot, the image signature dot and focus rings. It never fills a button.
- Radii are 12px for controls and buttons, 8px for the letter preview and 22px for the Style sheet's top corners. There are no drop shadows.
- Glass appears only on the Style sheet.
- Copy strings are exact: "Tap to write.", "Write or paste your letter.", "Your words stay on this device.", "Title (optional)", "Text is small. Try Story", "Text size: comfortable" / "Text size: small" / "Text size: tiny", "Clear", "Clear all?", "Done", "Share", "Save", "Copy image", "Copied", "Preparing", "Also send the words as text", "Save as my theme".

## Review Focus

1. **Whitespace-only or empty letters.** `fitText` returns `{ size: cap, blocks: [] }` without throwing, and Save and Share stay disabled. Tested in Task 2 (fit) and checked in Task 6 (disabled buttons).
2. **A single unbroken word longer than the line** (a URL, or "hahahaha..." x200). It breaks at grapheme boundaries and never overflows the safe width. Tested in Task 1.
3. **Text pasted with `\r\n` line endings, many consecutive blank lines, or leading and trailing whitespace.** It produces no empty paragraphs. Tested in Task 1.
4. **`localStorage` throwing, or holding corrupted or old-shaped JSON.** The app loads with defaults and unknown fields are dropped. Tested in Task 4.
5. **Typing or restyling while an export is still rendering.** A stale blob is never shared or saved; the version token is checked. Tested in Task 8.

### Task 1: Paragraphs, direction and wrapping

**Files:**
- Create: `package.json`, `js/layout.js`, `tests/helpers.js`, `tests/layout.test.js`

**Interfaces:**
- Produces, in `js/layout.js`:
  - `splitParagraphs(text: string): string[]`: normalises `\r\n` to `\n`, splits on one or more blank lines, trims each paragraph, and drops empty ones. Single newlines inside a paragraph become spaces.
  - `paragraphDirection(p: string): 'ltr' | 'rtl'`: from the first strong character. RTL if it falls in U+0590–U+08FF, U+FB1D–U+FDFF or U+FE70–U+FEFF.
  - `wrapParagraph(p: string, maxWidth: number, measure: (s: string) => number): string[]`

- [ ] **Step 1: Write the failing tests** in `tests/layout.test.js`:
  - `splitParagraphs('a\r\n\r\n\r\n  b  \n c\n\n')` deep-equals `['a', 'b c']`.
  - `splitParagraphs('   \n\n  ')` deep-equals `[]`.
  - `paragraphDirection('عزيزتي سارة')` equals `'rtl'`, `paragraphDirection('123 Dear')` equals `'ltr'`, and `paragraphDirection('« שלום')` equals `'rtl'`.
  - `wrapParagraph('aa bb cc', 3 * 10 * 0.5 + 0.1, fakeMeasure(10))` deep-equals `['aa', 'bb', 'cc']`.
  - Japanese: `wrapParagraph('やかんは今でもあの朝と同じ音で鳴ります', 50, fakeMeasure(10))` returns more than one line, every line measures 50 or less, and the joined lines equal the input.
  - Long word: `wrapParagraph('x'.repeat(200), 100, fakeMeasure(10))` gives lines that each measure 100 or less, and the joined lines equal the input.
  - Emoji: `wrapParagraph('hi 👨‍👩‍👧 🇮🇳 ok', 15, fakeMeasure(10))` never splits `👨‍👩‍👧` or `🇮🇳` across lines. Assert that each appears whole in exactly one line.
  - Devanagari: `wrapParagraph('क्षत्रिय नमस्ते', 20, fakeMeasure(10))` keeps each grapheme cluster intact: the joined lines without spaces equal the input without spaces.
  - No line starts or ends with a space.

- [ ] **Step 2: Run the tests.** Run `npm test` (or `node --test tests/`). Expected: FAIL, because `js/layout.js` exports nothing.

- [ ] **Step 3: Implement the three functions in `js/layout.js`.**
